# Flat Hunt Phase 1 (Core Tracker) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A usable, self-hosted flat-hunt tracker: profile (rent and/or buy, flat, places, radius, red flags, weights, income), listings with add/edit/delete, commute times, criteria check, scores, affordability, costs and map.

**Architecture:** Start from a copy of Car Hunt's code (`$CARHUNT` = the Car Hunt repository checkout). Keep its server pattern (`createApp`, JSON files in `DATA_DIR`, Basic auth, sync key, `/healthz`), page structure and dialogs, and replace the car domain with flats. Shared browser/Node modules (`criteria.js`, `money.js`) hold all rules so tests cover them.

**Tech Stack:** Node ≥ 18, Express 4, plain browser JavaScript, Leaflet from cdnjs, `node --test`.

**Spec:** `docs/design.md` (sections Profile, Listing record, Criteria/scores/affordability, Commute, Red flags, Security, Testing — phase 1 only).

## Global Constraints

- No personal data in the repository. Before every push: `grep -rn -i -f "$PATTERNS" --exclude-dir=node_modules --exclude-dir=.superpowers . || echo clean` must print `clean` (`$PATTERNS` is a private file outside the repo).
- Commits use the repo-local no-reply author already configured; no AI attribution lines.
- Node ≥ 18; runtime dependency `express` only in phase 1.
- All user-facing text in English (`en`), German (`de`) and Brazilian Portuguese (`pt`).
- `SITE_PASSWORD` required to start unless `ALLOW_OPEN=1`; only `/healthz` is public in phase 1.
- Writes to `DATA_DIR` are atomic; failed saves answer 500 `{ error: "save failed" }` and roll back in-memory changes.
- Score = round(Σ rating × weight ÷ Σ weights × 10), skipping missing ratings and zero weights. Rating keys: `price`, `size`, `commute`, `area`, `condition`, `contact`.
- Money shown in euros, de-DE/en-GB/pt-BR number formats as in Car Hunt.

### Task 3: Money module

**Files:** create `public/money.js` (UMD like `criteria.js`), `test/money.test.js`.

**Interfaces:**
- Produces: `TRANSFER_TAX` (state → percent), `TRANSFER_TAX_CHECKED` (`"2026-06"`), `annuity(principal, apr, years) → monthly`, `purchaseCosts(price, profile) → { transferTax, notary, agent, total }`, `buyMonthly(price, profile) → { loan, monthly }`, `affordability(monthly, profile) → { share, level: "fits" | "tight" | "too-much" | "unknown" }`, `warmRent(listing) → number | null`.

- [ ] **Step 1: Failing tests:**
  - `annuity(200000, 3.6, 25)` ≈ 1011.98 (±0.05); `annuity(1200, 0, 1)` = 100.
  - `purchaseCosts(300000, {buy:{state:"NW", agentFeePct:3.57}})` → transferTax 19500, notary 6000, agent 10710, total 36210.
  - `buyMonthly(300000, { buy: { state: "BY", agentFeePct: 0, equity: 60000, apr: 3.6, years: 25 } })` → loan = 300000 + 10500 + 6000 − 60000 = 256500, monthly ≈ annuity(256500, 3.6, 25).
  - `affordability(1000, { money: { netIncome: 3000, affordShare: 0.33 } })` → share 0.333…, level "tight"; 900 → "fits"; 1200 → "too-much"; netIncome 0 → "unknown".
  - `warmRent({ warmRent: 950 })` = 950; `{ coldRent: 800, utilities: 180 }` = 980; `{ coldRent: 800 }` = null.

- [ ] **Step 2: Implement:**

```js
const TRANSFER_TAX = { BW: 5.0, BY: 3.5, BE: 6.0, BB: 6.5, HB: 5.5, HH: 5.5, HE: 6.0, MV: 6.0, NI: 5.0, NW: 6.5, RP: 5.0, SL: 6.5, SN: 5.5, ST: 5.0, SH: 6.5, TH: 5.0 };
const TRANSFER_TAX_CHECKED = "2026-06";
const NOTARY_PCT = 2.0;
function annuity(principal, apr, years) { const n = years * 12, r = apr / 1200; if (principal <= 0) return 0; return r ? principal * r / (1 - Math.pow(1 + r, -n)) : principal / n; }
function purchaseCosts(price, p) { const t = price * (TRANSFER_TAX[p.buy.state] || 0) / 100, n = price * NOTARY_PCT / 100, a = price * p.buy.agentFeePct / 100; return { transferTax: Math.round(t), notary: Math.round(n), agent: Math.round(a), total: Math.round(t + n + a) }; }
function buyMonthly(price, p) { const loan = Math.max(0, price + purchaseCosts(price, p).total - p.buy.equity); return { loan, monthly: annuity(loan, p.buy.apr, p.buy.years) }; }
function affordability(monthly, p) { const inc = p.money.netIncome; if (!inc || monthly == null) return { share: null, level: "unknown" }; const s = monthly / inc, a = p.money.affordShare; return { share: s, level: s <= a ? "fits" : s <= a + 0.05 ? "tight" : "too-much" }; }
function warmRent(l) { if (l.warmRent != null) return l.warmRent; if (l.coldRent != null && l.utilities != null) return l.coldRent + l.utilities; return null; }
```

Note in the test file header and on the page: the rates were checked in June 2026; buyers must verify the current rate for their state.

### Task 4: Commute module and server integration

**Files:** create `lib/commute.js`, `test/commute.test.js`; modify `server.js`.

**Interfaces:**
- Consumes: profile `places` (Task 2), `app.locals.fetchImpl`.
- Produces: `travelMinutes(from, place, fetchImpl, { now, ms }) → Promise<number | null>`; `commuteFor(point, places, fetchImpl, opts) → Promise<Array<{ minutes, checkedAt } | null>>` (one entry per place, same order).

- [ ] **Step 1: Failing tests** with a stub fetch:
  - car → requests `router.project-osrm.org/route/v1/driving/<lon>,<lat>;<lon>,<lat>` and returns `round(duration/60)`.
  - bike → requests `routing.openstreetmap.de/routed-bike/route/v1/driving/...`.
  - transit → requests `api.transitous.org/api/v1/plan?fromPlace=<lat>,<lon>&toPlace=<lat>,<lon>&time=<ISO of next Mon–Fri at place.time, Europe/Berlin>&arriveBy=true` and returns the minimum `itineraries[].duration` in minutes.
  - any failure or empty result → null; timeout (default 5000 ms) → null.
  - next weekday: from Saturday 2026-10-24 10:00 with time "08:00" → Monday 2026-10-26 08:00 Europe/Berlin = 2026-10-26T07:00:00Z (summer time ends on 25.10.2026, so Berlin is UTC+1); from Wednesday 2026-07-01 09:00 with "08:00" → Thursday 2026-07-02T06:00:00Z (UTC+2).

- [ ] **Step 2: Implement** using the `getJson` helper pattern from `lib/geo.js` (UA, AbortController timeout). Compute Europe/Berlin offset with `Intl.DateTimeFormat("en-GB", { timeZone: "Europe/Berlin", timeZoneName: "shortOffset" })`.

- [ ] **Step 3: Server:** after geocoding on `POST /api/listings` and on an address change in `PATCH /api/listings/:id/listing`, set `listing.commute = await commuteFor(point, profile.places, fetchImpl)` (empty array when no places). On `PUT /api/profile`, if `places` changed, mark every listing's `commute` stale by setting `commuteStale: true` (the page offers "Recalculate commute times", which calls a new `POST /api/listings/recalc-commute` — password only — that recomputes sequentially with a 1-second pause and clears `commuteStale`). Tests for all three with stub fetch.
